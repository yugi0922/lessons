第7章：Attention と Transformer
必要な情報を、その都度参照する

RNNの「記憶を持ち回る」仕組みから、関連する情報を直接参照する仕組みへ。小さな数値例を出発点に、文章を生成するまでの道筋をつなぎます。

発表原稿（Markdown）各図の数字は、実モデルの実測値ではなく説明用です。
今日の到達点
  • Attentionが「重みを計算して情報を混ぜる」仕組みだと説明できる。
  • Self-Attentionと位置情報が、それぞれ何を担うか説明できる。
  • Transformerの入力から出力までを追い、学習の並列化と生成の逐次性を区別できる。
① 圧縮から参照へ→② 文脈を取り込む→③ 単語を予測する→④ BERTとGPTへ

7.1 Attention — 必要な情報を参照する

6章の復習：RNN系の2つの壁

6章では、隠れ状態を更新しながら系列を1語ずつ読むRNNと、記憶を保ちやすくしたLSTM・GRUを学びました。最後のSeq2Seqでは、Encoderの記憶からDecoderが翻訳文を作りました。

壁① 固定長ボトルネック

基本的なSeq2Seqでは、入力文の情報を最後の固定長の状態に集約します。長い文の詳細を保つのが難しくなります。

壁② 時間方向の逐次処理

RNNの次の隠れ状態を計算するには、前の状態が必要です。系列内の全位置をまとめて計算できません。

Attentionはまず壁①を緩和します。RNNにAttentionを追加してもRNN自体の逐次処理は残ります。壁②への大きな転換が、後半のTransformerです。

コマ送り

翻訳する語が変わると、参照先も変わる

最後の状態だけに頼る代わりに、入力の各位置の状態を残し、出力する語に応じて参照の配分を変えます。

例えば「会議室」に関する訳語を作る場面と、「15時」に関する訳語を作る場面では、必要な情報が違います。Attentionは、その都度どの入力をどれだけ使うかを計算します。

準備：単語を、計算できるベクトルにする

モデルに入るのは文字列のままの単語ではありません。文章をトークンという単位に分け、IDを付け、埋め込み（Embedding）で数値の並びに変換します。6章のコードに出てきたnn.Embeddingの役割です。

文章：「今日の会議は15時」
↓ トークン化
例：［今日］［の］［会議］［は］［15］［時］
↓ ID → 埋め込み
各トークン → ベクトル　例：［0.2, −0.5, …］

実際の分割はトークナイザー次第で、1トークン＝1単語とは限りません。本章の日本語の分割は説明用です。ベクトルの各成分にも、人間が読める決まった意味があるとは限りません。

Query・Key・Value：探す手掛かりと、取り出す中身

検索を思い浮かべてください。探したい内容をQuery、照合する手掛かりをKey、取り込む情報をValueと呼びます。3つともベクトルです。

Q：何を探す？

情報を取り込む側が持つ、検索用の手掛かり。

K：何と照合する？

各参照先が持つ、照合用の手掛かり。

V：何を取り込む？

照合の結果に応じて混ぜる、各参照先の情報。

QとKの内積からスコアを作り、2章で学んだSoftmaxで合計1の配分に変換し、その配分でVを加重平均します。辞書のように1件を選ぶだけでなく、複数の参照先から少しずつ情報を取り込めます。

計算を追う

3つのValueを、どんな配分で混ぜる？

スコアをSoftmaxで重みに変え、Valueを足し合わせます。出力は、単語ではなくベクトルです。

ここがAttentionの出力出てくるのは「会議室」という文字列ではなく、参照先の情報を取り込んだ新しいベクトルです。文章を出すには、さらに後段の処理が必要です。

注目度そのものを、固定パラメータとして覚えるわけではありません。学習するのはQ・K・Vを作る変換などのパラメータです。同じモデルでも、入力や位置が変われば注目度も変わります。

補足：数式では、3つの操作を1行で書ける
Attention(Q, K, V) = softmax(QKᵀ / √dk)V
部分図解との対応
QKᵀ参照する側と、各参照先のスコアをまとめて計算
÷ √dk内積のばらつきが次元数とともに大きくなる影響を調整
softmax各Queryについて、参照先の重みの合計を1にする
× Vその配分でValueを混ぜる

これがScaled Dot-Product Attentionです。初期のRNN向けAttentionには別のスコア計算法もありました。Attentionの共通の考え方が「スコア → 配分 → 加重和」で、ここではTransformerで使われた方式を扱います。

確認①Attentionの出力は、単語そのものですか。それとも情報を取り込んだベクトルですか？

7.2 Self-Attention — 文の中で情報を交換する

同じ入力から、Q・K・Vを作る

ここまでは「翻訳文を作る側が、入力文を見る」例でした。次は同じ文の各トークンが、同じ文の他の位置を参照します。これがSelf-Attention（自己注意）です。

入力ベクトルXに、それぞれ別の学習可能な変換をかけます。Q = XW_Q、K = XW_K、V = XW_Vです。同じ元データでも、探す役・照合される役・情報を渡す役に合わせて変換を分けます。Q＝K＝Vという意味ではありません。

行を選ぶ

行は「誰が見る？」、列は「誰を見る？」

各行は、1つのトークンから見た参照先の配分です。各行の合計は1です。

「動物は、疲れて、道を、渡らなかった」という例なら、「渡らなかった」の表現に「動物」や「疲れて」の情報を取り込めます。RNNのように隣を何回も経由せず、1層の中で離れた位置と直接情報を交換できます。ただし、1回の参照で意味を完全に理解するという意味ではありません。

図の配分は説明用です。学習後のヘッドが必ず「主語」などの役割に分かれるわけではなく、注目度だけでモデルの判断理由を断定することもできません。

位置情報：並び順も入力に含める

位置情報を持たないSelf-Attentionでは、語の内容は照合できても、どの位置にあるかを直接の手掛かりにできません。「犬 が 人 を 噛んだ」と「人 が 犬 を 噛んだ」では、同じ語でも役割が変わります。

切り替える

「犬」は同じでも、「何番目の犬」かが違う

語順と位置情報を切り替えると、位置を区別する手掛かりを確認できます。

原型Transformerでは、各トークンの埋め込みに位置ごとのベクトルを加算します。「単語の情報＋位置の情報」をAttentionに渡すことで、並び順を使えるようにします。

補足：位置情報の方式と、正確な言い方

位置情報もMaskもないSelf-Attentionは、入力の順番を入れ替えると出力も対応して入れ替わります。出力がまったく同じになる「不変」ではなく、置換同変です。入門では「内容だけでは、語順を識別する手掛かりが足りない」と押さえれば十分です。

方式位置の伝え方
Sinusoidal原型Transformer。sin・cosによる固定ベクトルを加算
学習型位置ベクトルも学習。BERTなど
RoPEQ・Kを位置に応じて回転させ、相対的な位置関係をスコアに反映。単純な加算方式とは異なる

固定の式で長い位置のベクトルを作れても、未学習の長さで性能が保証されるわけではありません。

Multi-Head：別々の変換で、複数の配分を作る

1組だけで情報を混ぜると、異なる関係を同時に表しにくくなります。そこで別々の変換でQ・K・Vを作るAttentionを並べ、結果を連結します。これがMulti-Head Attentionです。5章で、複数のフィルタが異なる特徴を取り出したことを思い出してください。

次元を見る

512次元を、64次元×8ヘッドで扱う

1ヘッドの出力を連結し、出力用の線形変換でモデルの次元にそろえます。

この設定では、各ヘッドが(10, 64)を出し、8個の連結で(10, 512)になります。さらに出力変換W_Oを適用します。「512次元の1ヘッド」と「64次元の8ヘッド」を比べると、主要な行列演算の計算量は概ね同程度です。

補足：行列shapeを通して追う（演習2用）

バッチ次元は省略します。@は2章でも使った行列積、.Tは転置です。

X              : (10, 512)   10トークンの入力
W_Q, W_K, W_V  : (512, 64)   1ヘッド分の変換
Q, K, V        : (10, 64)
Q @ K.T        : (10, 10)    全位置の組み合わせ
weights        : (10, 10)    行ごとにSoftmax
weights @ V    : (10, 64)    1ヘッドの出力
8ヘッドを連結   : (10, 512)
連結結果 @ W_O : (10, 512)   W_Oは(512, 512)

保たれるのはまずトークン数です。1ヘッドの特徴次元は64に変わり、連結と出力変換を経たMulti-Head全体では入力と同じ512次元に戻ります。幅をそろえることは、後の残差接続にも必要です。

確認②Self-Attentionは、文を1本のベクトルにまとめますか。それとも各位置に文脈を取り込んだベクトルを返しますか？

7.3 Transformer — 入力から次の語までつなぐ

全体像：Attentionと全結合層を積み重ねる

2017年のTransformerは、系列を扱う中心の仕組みとしてRNNやCNNを使わず、Attentionと位置ごとの全結合層を採用しました。まずは、原型の翻訳用Encoder–Decoderを見ます。図は両側とも上から下へ流れます。

順にたどる

入力文と、生成途中の文は、別の入口から入る

Encoderは入力文の表現を作り、Decoderは生成済みの語とEncoderの出力を使って次の語を予測します。

3種類のAttentionは、情報を混ぜる計算は同じで、参照先と見える範囲が違います。

種類Qの元K・Vの元役割
EncoderのSelf-AttentionEncoderの各位置の表現同じEncoder内の表現入力文の各位置が入力文全体を参照
DecoderのMasked Self-AttentionDecoderの各位置の表現同じDecoder内の表現生成済みの文脈を参照。未来は参照しない
Cross-AttentionDecoder側の表現Encoderの最終出力入力文を参照して、訳語の予測に使う

各層では、前のサブ層・層から受け取った表現を線形変換してQ・K・Vを作ります。常に最初の埋め込みだけを見るわけではありません。Paddingなどの無効な位置は、別のMaskで除外します。

FFN・残差接続・LayerNormの役割

Attention：位置の間で混ぜる

他の位置から情報を取り込み、各位置のベクトルを更新します。

FFN：各位置の中で加工する

同じ全結合ネットワークを各位置に適用します。この段階では他の位置のベクトルと混ぜません。

Feed Forward Network（FFN）は、例えば「512次元 → 2048次元 → 512次元」の2層の全結合層です。間にReLUなどの非線形関数を入れます。5章のResNetと同じ残差接続で元の入力も足し、LayerNormで各トークンの特徴のスケールを整えます。

補足：原型Transformerの式と、現在の実装での違い
# 各位置に同じFFNを適用する（概念コード）
h = relu(x @ W1 + b1)       # (n, 512) → (n, 2048)
y = h @ W2 + b2            # (n, 2048) → (n, 512)

# 原型Transformerの残差と正規化（Dropoutは省略）
out = LayerNorm(x + SubLayer(x))

これは原型のPost-LN配置です。正規化を前に置くPre-LNや、RMSNormを使うモデルもあります。LayerNormは特徴次元方向で正規化してから、学習可能なスケール・バイアスを適用します。最終出力が常に平均0・分散1という意味ではありません。

Mask：見てよい範囲を決める

翻訳文や文章の生成では、次の語は、まだ生成していない未来の語に頼れません。学習中にも同じ条件を守るため、DecoderのSelf-Attentionで後ろの位置への参照を禁止します。

Maskを切り替える

未来のスコアを−∞にすると、重みは0になる

入力位置と、その位置で予測する次の語を対応させます。自分の位置を見ても、正解を見たことにはなりません。

入力と正解を1位置ずらすのもポイントです。入力Iの位置では、次の正解likeを予測します。対角線上の自分を参照しても、予測すべき正解を直接見てはいません。

Encoderは、翻訳元の入力文全体が既にあるので、通常はこの未来を隠す因果Maskが不要です。これは「EncoderにはどんなMaskも不要」という意味ではありません。

学習はまとめて計算、生成は1語ずつ

6章のSeq2Seqで出てきたteacher forcingを思い出してください。学習時には、生成済みの語の代わりに正解文の直前までを入力できます。正解の各位置がそろっているため、Maskを守りながら全位置の予測をまとめて計算できます。

モードを切り替える

同じ「次の語の予測」でも、入力がそろう時点が違う

学習時は正解文があるので複数位置をまとめて予測でき、生成時は出した語を次の入力に追加します。

一方、通常の自己回帰生成では、次の語が決まってから、その語を含めて次を予測します。Transformerだから文章全体を一度に生成できる、ということではありません。

比較点RNN / LSTMTransformer
学習時の系列内の計算前の隠れ状態を待つ各層で位置をまとめて計算できる
離れた位置への経路間の位置を経由Self-Attentionで直接参照できる
通常の自己回帰生成次の語を順に決定次の語を順に決定
長い入力の負担系列長に応じて逐次段数が増える全位置どうしのAttentionでは組み合わせが二乗で増える

Transformerの利点は、学習時にGPUの得意な大きな行列演算へまとめやすいことです。実際の速度は系列長、モデル幅、実装、ハードウェアに依存します。

補足：長い文のコストとKVキャッシュ

長さnの通常の全結合Self-Attentionには、n×nの参照の組み合わせがあります。ほかの次元を固定すると、その部分の演算量はO(n²)です。長さを2倍にすると組み合わせは4倍ですが、FFNなども含むモデル全体の時間・メモリが必ず4倍になるわけではありません。

スコア行列を丸ごと保存する素朴な実装では、その保存量も二乗です。FlashAttentionのように行列を丸ごと保存しない実装もあります。また、生成時にはKVキャッシュで過去のK・Vを再利用し、過去の計算をすべてやり直すことを避けます。それでも次の語の決定は通常、順番に進みます。

確認③学習時には複数位置をまとめて予測できるのに、通常の文章生成では順番に語を決めるのはなぜでしょう？

7.4 BERTとGPT — 見える範囲と構成の違い

原型Transformerの考え方は、目的に合わせた構成へ発展しました。代表例が、文全体を参照するEncoder系のBERTと、前から続きを予測するDecoder系のGPTです。

構成を比較

GPTのDecoderには、翻訳元を見るCross-Attentionがない

BERTはEncoder系、GPTはCross-Attentionを持たないDecoder-only系の代表例です。

観点BERT系の代表的な構成GPT系の代表的な構成
参照範囲入力の前後を参照各位置から、その位置までを参照
事前学習の例隠したトークンを当てる次のトークンを当てる
用途の例分類、固有表現抽出、検索向け表現文章生成、対話、指示による分類・抽出
利用時の選択目的に合う学習済みモデルを使う、追加学習するなど指示調整されたモデルへのプロンプト、追加学習など

「BERTなら必ず追加学習」「GPTなら無調整で必ず解ける」という区分ではありません。用途・精度・データ・コスト・運用条件で判断します。検索用のベクトル表現には、その目的で学習したモデルを選ぶことも大切です。

発展：スケーリング則と、画像・音声への展開（時間がある場合）

大きく学習できることの意味

モデル規模・学習データ量・計算量と損失の間には、一定の設定や範囲で予測可能な関係が観測されています。これがスケーリング則です。パラメータ数だけを増やせばよいという法則でも、個別タスクの能力をすべて予測できる保証でもありません。

ある規模で能力が突然現れたように見える「創発」の報告もありますが、評価指標の選び方で急激に見える場合があるという研究もあります。損失の滑らかな改善と、個別能力の現れ方は分けて考えます。非公開モデルの推定パラメータ数は、規模の説明の根拠には使いません。

各パッチをベクトルにする

各パッチを線形変換し、位置情報とともにTransformerへ渡します。原型の分類用ViTでは、分類用トークンも追加します。

CNNは局所性などの事前知識を構造に持ち、ViTはパッチ間の関係をAttentionで学びます。データ効率は学習方法・事前学習・データ拡張などでも変わるため、「少量データなら必ずCNN」とは言い切れません。音声でも、スペクトログラムなどから系列表現を作ってTransformerを使えます。

まとめ — 今日持ち帰る3つ

  • Attentionは、参照先の重みを入力に応じて計算し、Valueを混ぜてベクトルを返す。
  • Self-Attentionは各位置に文脈を取り込む。位置情報が語順の手掛かりを与える。
  • Transformerは学習時に各位置をまとめて計算できる。通常の文章生成は、次の語を順に決める。

次章では、Decoder系Transformerを土台にしたLLMの学習、生成時の選び方、RAGなどのアプリケーションへの組み込みを扱います。

演習・ディスカッション

1. Attentionは何を返す？
重みが［0.2, 0.3, 0.5］、Valueが順に［1, 0］、［0, 1］、［1, 1］のとき、出力を計算してください。その出力は単語ですか？

解答例を見る

0.2［1, 0］＋0.3［0, 1］＋0.5［1, 1］＝［0.7, 0.8］。情報を混ぜたベクトルです。単語を選ぶには後段の処理が必要です。

2. shapeを確認する（任意）
20トークン、モデル幅768、12ヘッドで、Q・K・Vの各ヘッドの次元を64とします。1ヘッドのQ・K・V、重み行列、Multi-Headの最終出力のshapeは？ バッチ次元は省略します。

解答例を見る

Q・K・V：(20, 64)。重み行列：(20, 20)。各ヘッドの出力(20, 64)を12個連結し、出力変換した最終出力：(20, 768)。

3. Maskと並列化を説明する
入力が［開始, I, like］、正解が［I, like, cats］のとき、入力Iの位置はどこを参照できますか？ なぜ学習では3位置をまとめて予測でき、生成では通常できないのでしょう？

解答例を見る

入力Iの位置は［開始, I］を参照でき、後ろのlikeは参照できません。学習時は正解文が既にあり、ずらした入力を用意して因果Maskの下で全位置を計算できます。生成時は次の語がまだ決まっておらず、出力した語を入力へ追加して次の予測に進みます。

4. 分類モデルを選ぶ
問い合わせメールを「請求・技術・その他」に分類します。どんな情報を確認して、Encoder系の分類モデルや指示調整済みLLMを選びますか？

解答例を見る

正解ラベル付きデータの量、必要精度、メールの長さ、処理件数、遅延、機密性、費用を確認します。例えば大量・低遅延の定型分類なら、小さなEncoder系モデルの追加学習を検討できます。ラベルが少なくカテゴリを試行中なら、指示調整済みLLMでまず評価する選択もあります。いずれも実データの検証用集合で比較します。
